## Known logic gaps (do not copy into code)
- Footer says "no LLM" on screens 1-5; the footer should also state that the AI agent only proposes.
- Screen 1 shows demo wardrobe and the upload dropzone at once.
- Screen 3: a render error has no retry action; the screen does not say that an errored or unrated combination counts as "would not wear" in the certificate; the counter ignores the live cap and the 6 preparation units; rendering the Aster column is not justified by the decision-relevant rule.
- Screen 4: certificate explains failures by manufacturer claims, not by the ratings that cause them, and has no note on unrated combinations.
- Screen 4b: zero-purchase coverage is claimed with no "would wear" rating and no outerwear, which contradicts the "Satisfies" definition.
- Screen 5: "Remaining 6" reads as a budget; the live toggle next to DEMO is unclear; the share card includes garment photos without a scope choice.
- Screen 6: no step-by-step agent stream, no 2-3 outfits with 0-100 scores; consent boxes shown pre-ticked; no "not stored / 24 h" text for a personal photo.
- Screen 7: one outfit only; the render is a single scene with background and signage, while renders are per item, not layered; no "what is missing" section and no "AI proposal, basket verified by the minimality certificate" caption.
- Screen 8: "Go to purchase" implies checkout, which the demo does not have; no total for delivery; missing stock or hours should show as "no data".
- Bottom navigation (Wardrobe, Shop) and a 12-item wardrobe with trousers and shoes imply accounts, persistence and lower-body garments, which are out of scope in the brief.
- Demo mode replays saved transcripts, yet screen 6 shows a personal photo and live-style counters.
