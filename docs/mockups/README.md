## Known logic gaps (do not copy into code)
- Footer says "no LLM" on screens 1-5; the footer should also state that the AI agent only proposes.
- Screen 1 shows demo wardrobe and the upload dropzone at once.
- Screen 3: a render error has no retry action; the screen does not say that an errored or unrated combination counts as "would not wear" in the certificate; the counter ignores the live cap and the 6 preparation units; rendering the Aster column is not justified by the decision-relevant rule.
- Screen 4: certificate explains failures by manufacturer claims, not by the ratings that cause them, and has no note on unrated combinations.
- Screen 4b: zero-purchase coverage is claimed with no "would wear" rating and no outerwear, which contradicts the "Satisfies" definition.
- Screen 5: "Remaining 6" reads as a budget; the live toggle next to DEMO is unclear; the share card includes garment photos without a scope choice.
- Screen 6: no step-by-step agent stream, no 2-3 outfits with 0-100 scores; consent boxes shown pre-ticked; no "not stored / 24 h" text for a personal photo.
- Screen 7: one outfit only; the render is a single scene with background and signage, while renders are per item, not layered; no "what is missing" section and no "AI proposal, basket verified by the minimality certificate" caption.
- Screen 8: "Go to purchase" implies checkout, which the demo does not have; no total for delivery; missing stock or hours should show as "no data".
- Bottom navigation (Wardrobe, Shop) and a 12-item wardrobe with trousers and shoes imply accounts, persistence and lower-body garments, which are out of scope in the brief.
- Demo mode replays saved transcripts, yet screen 6 shows a personal photo and live-style counters.

## Landing page v1

File: `landing-v1.png` (793 x 1983, one tall bitmap). Source: generated by the team's design tooling, 21 Oct 2026. Static visual reference, not a working page. All people, garments and imagery are synthetic and illustrative; PLN figures are the synthetic solver example (C 90, cheaper baskets 0 / 40 / 60), not a shop offer.

Implementation notes (PR4, front):
- Implement as the site index (`/`); the app lives behind the CTA "Try the demo" (the mockup says "Explore the prototype"; use "Try the demo").
- Two entry points in the header: "For shoppers" (wardrobe, separate try-on previews, justified purchase) and "For retailers" (catalogue recommendations, pilot offer).
- Copy in English. The guided tour starts from the landing and from a jury section.
- Order: hero, problem, 3 steps, certificate example, zero purchases, trust strip, AI Stylist (planned), retailers (pilot concept), jury invitation + FAQ, close, footer.

Content fixes needed before implementing:
- Mark planned features visibly as "Planned": AI Stylist (already labelled "Coming next"), retailer integration and the "One-store basket concept"; the retailer CTA must not imply a live service ("Request a pilot" / contact, no checkout).
- Add a privacy line: shoppers upload garment photos only, no face photos; try-on uses a synthetic model; the provider (YouCam) keeps uploads and results 24 h.
- AI Stylist caption must say the agent proposes and the solver certifies the purchase; the footer line "Purchase logic: deterministic" is fine, add "AI proposes (planned)".
- Add the scope caveat to the certificate: the minimum holds for the chosen catalogue, declared needs and the shopper's own ratings. Keep the "Synthetic example" label next to every number; remove the prices if the label cannot stay visible.
- Show "Illustrative previews" and "synthetic model" labels on the hero imagery, not only in small print; no real-photo or fit implication.
- Remove or verify any claim of measured benefit (none in the mockup; do not add uplift, returns or customer numbers). The mockup shows no testimonials or logos; keep it that way.
- Fix the rendering glitch in the trust strip headline ("calculation" partly blue) and the garbled tiny footer text; the "Try the demo" button replaces "Explore the prototype".
- Keep the render error wording: an image error is unresolved, not a dislike (matches the brief).
