## Manual device acceptance (not claimed as automated)

1. Android Chrome/Edge: open `/judges/`, install from the native prompt, launch from the icon, dismiss any optional UI and confirm the chosen demo and saved wardrobe persist.
2. iPhone Safari: use the app's Share → Add to Home Screen instructions, launch standalone, check keyboard/safe areas and camera/file fallback.
3. Switch offline: own clothing photos and saved examples remain; live AI/forecasts/new previews explain that a connection is required. Reconnect and verify data persists after a service-worker update.
4. Add a real garment-only photo with consent; use the synthetic avatar selected in My style. The single authorized live YouCam probe is already used, so any additional physical garment render requires a separately allocated run.

Local profiles are device storage, not authenticated cloud accounts. File transfer is explicit, not automatic synchronization. Personal-photo try-on is disabled; preview style does not prove size. Operator endpoints remain unavailable if the separate existing operator secret is absent; no secret is created or rotated by this release. Real provider verification and deployment receipts are recorded separately when executed.

## Independent review corrections

The requested ecommerce conversation returned three P1 findings and two P2 findings. All were reproduced without additional paid calls.

- A changed product name, source URL or photograph invalidates that product's pair ratings. Other products keep their assessments; a price-only edit keeps the assessment and recomputes cost. The certificate cannot silently inherit a verdict from a different product.
- Trip and wardrobe-needs views read the current profile store before rendering or editing. A completed AI save is visible without reload, and later UI edits preserve it. The browser test preloads both views, applies `save_plan`/`save_shopping_list`, navigates, edits and reloads.
- A transient status GET failure retains its known render key. The same valid capability can resume GET on reload or through **Check existing preview**, without a replacement POST or new unit reservation. An uncertain submission without a key remains UNKNOWN and cannot be automatically resubmitted.
- Image inspection is limited to one bounded image per model turn; additional images are explicitly deferred as UNKNOWN. Previously inspected base64 is retired while tool text and provenance remain. Three 140 KB photos complete through successive bounded turns in the real provider adapter test.
- The retained landing layout now describes the implemented AI Stylist rather than calling it planned.
- The mobile gallery's Remove control sits below its thumbnail; it no longer intercepts a tap intended to open that photo. The actual UI regression checks product substitution, price-only edits and failed-GET recovery at 390/1280, with zero render POSTs.
